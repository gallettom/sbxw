    Skills in your sandboxes

    Type the command in a sandbox’s agent pane. A sandbox has a kit’s commands when sbxw.toml’s kits lists it; a sandbox created before the kit was added needs sbxw rm then sbxw up. Default skills are run by sbxw on its own — a hook, a web UI button, or another skill; manual ones only when you type them. Hover a tag for the reason.

    Agent skills kit assets/agent-skills
    /i-have-adhd default ayghri/i-have-adhd

    Shapes every answer for a reader with ADHD: the next action first, numbered steps, state restated each turn, specific time estimates. Always on through a session-start hook; “stop adhd mode” turns it off for the session.

    /archify default tt-a1i/archify

    Validated, interactive HTML diagrams — architecture, workflow, sequence, data flow, lifecycle — from a description, pasted Mermaid, or the repository itself.

    /handoff manual mattpocock/skills

    Compacts the current conversation into a handoff document a fresh agent can pick up. Pass what the next session is for.

    /grill-me manual mattpocock/skills

    A relentless interview to sharpen a plan or design: questions in rounds, each with a recommended answer, until nothing is left assumed.

    /grilling manual mattpocock/skills

    The interview /grill-me runs. The agent also reaches for it on its own when you ask to be grilled.

    /frontend-design manual anthropics/skills

    Guidance for distinctive, intentional UI design — aesthetic direction, typography, choices that don’t read as templated defaults. Used on its own when the agent builds UI.

    /brag manual latent-spaces/brag

    A short, shareable launch video of the project, with music, motion and share copy.

    /brag-slim manual latent-spaces/brag

    The same launch video from a project or a website URL, built only with the tools already installed.

    Code map kit assets/codemap
    /codemap default

    Writes or refreshes the project’s code map in .sbxw-artifacts/codemap/: what the code does, why it is built that way, and where each idea lives. Agents read it before the source.

    /codemap-lens default

    Retells the code map for one reader — a product owner, a new joiner — as a separate document beside it.

    Help — no sandboxes showing?

    The sidebar lists exactly what the sbx CLI reports. An empty list nearly always means sbx has nothing to report — not that your sandboxes are gone. Run the commands below on the machine sbxw itself runs on (a terminal on your host, not a sandbox pane), then hit Refresh.

    1 Log in to sbx

    An unauthenticated CLI lists no sandboxes at all. This is a one-time step per machine, and it opens a browser to finish.

    sbx login
    2 Restart the sbx daemon

    Try first to run sbx to see if it suggest you to restart it (After an update)

    sbx

    Already logged in and the list is still empty? The daemon behind the CLI is wedged or not running. Start it again in the background — it keeps running after you close the terminal, and writes what happened to ~/.sbx/daemon-restart.log.

    nohup sbx daemon start >> ~/.sbx/daemon-restart.log 2>&1 &

    Give it a couple of seconds, press Refresh, and check sbx ls. If that still comes back empty, the log file above says why.
