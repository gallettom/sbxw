# sbxw desktop, phase 3: creating a sandbox

Thread `desktop-create` of the shared plan (branch
`sbxw/team-p-d562f04a5ca7a14efc3133c0b49c15dc`). Parity target: the web UI's
`assets/js/create.js`, the bring-up part of `assets/js/sandboxes.js`
(`postBringUp`, `askHostAccess`, the corner cards). Built on desktop-shell's
`src/feat/` (features declared in one place, core-drawn confirmations).

## What was built

| Part | Where | What |
|---|---|---|
| Model | `src/feat/create/model.rs` | The form and its rules, no daemon, no window: name cleaning as typed and the daemon's name rule, taken names (with `host~name` off this machine), folders (the first is the workspace, the others RO or RW, nested ones refused), restricted sub-folders (pick inside a read-write folder only, typed paths checked, strict or soft, no access or read-only, dropped when their folder goes), the carve preview (stale answers dropped by sequence), ports (refused when not 1 to 65535), kit folders, the template offer, the request body, what the sandbox would reach beyond its workspace, the daemon's answers (ready, 409 consent, failure), and bring-ups from `provision` events |
| Feature | `src/feat/create/mod.rs` | 14 intents (`create_open` ... `create_dismiss`, all Direct), `on_answer` for every call, `on_event` for `provision`, two top-bar extras, `core_only: ["approved"]`. The form lives in the core (one `State`), never in Luau |
| Screens | `screens/create.luau` (modal 640 pt), `screens/create-jobs.luau` (panel "New sandboxes") | The chooser, the workspace form, the chat form; the bring-ups with every step, the running one's detail, the failure's reason, Retry and Dismiss |
| Stand-in | `src/feat/create/standin.rs` | A folder tree, favourites, the native picker, kit folders, template state, a carve preview, and bring-ups that publish their steps 350 ms apart (`publish_after`), with an optional host-access question (`create_consent`) and a failure once at the kits step (`create_fail`) |

| Demo | `scripts/demo-create.sh` | A whole creation in the whole window against the stand-in (below) |
| Docs | `docs/screens.md`, section `### create` | `data.create`, the screens, the extras, every intent |

### The two confirmations (core-drawn)

1. **Before sending**, when the sandbox would reach more of this machine
   than its workspace: each extra folder (RO or RW), each kit folder, each
   published port (with its hostname), Claude in Chrome. The lines come from
   the core's copy of the form (`Form::grants`). A workspace alone asks
   nothing, as in the web UI.
2. **When the daemon refuses** for want of host access its `sbxw.toml` asks
   for (`409 {consent: {config, grants}}`): title "Allow host access?",
   the file, the daemon's own lines under "You grant:"
   (`Confirm::grant_lines`), the web UI's warning, Allow in red. Only on
   Allow does the core put those exact lines in `approved` and send again.
   `approved` is `core_only`: no intent declares it, `act` never sets it,
   and the core refuses any call carrying it that is not a confirmed dialog's
   (tested: `approved_lines_only_ever_come_from_the_daemons_question`).

### Refusals shown in plain words

| Who refuses | Where it shows |
|---|---|
| Name rule, taken name (core, as the web UI) | Under the name field, and beside Create |
| Nested folders (core) | The extra folders' hint, in red |
| A port that is not a number | Beside Create |
| Carve preview (`/api/carve/preview` `{ok: false, error}`) | On each restriction, the preview in red; Create held |
| A typed restricted path (absolute, no `..`, inside its folder) | Under the pick box |
| Favourites (`'x' is not a folder`), native picker (`no native folder picker found`) | The dialog's error line |
| A folder that cannot be read | In the folder list |
| The bring-up (`bad sandbox name`, `already exists`, sbx's error, an unreachable host, a clone that failed) | On the job's card, with Retry |

## Web features not ported, and why

| Web feature | Status |
|---|---|
| Alt+N (⌃⌥N) to open the chooser | Not ported: the app has no global shortcut registry for features yet. The top bar's New does it |
| "Ready" blue dot in the sidebar when no pane is free | Not needed: the core's `open_terminal` with `pane: "spare"` takes an empty pane or adds one; with four busy panes it uses what the core does for `spare` |
| Remember the host per browser (localStorage) | Remembered for the app's run only (`State::last_host`), not across restarts |
| Host monitor (`monitor_cmd`) | Not part of creation; not ported here |
| Agent, model and kits choice at creation | The web UI has none at creation: the agent and the kits come from `sbxw.toml` (the Setup dialog's Kits tab, thread desktop-setup), the model is chosen per thread |
| Templates dialog (`templates.js`: list, save, remove, disk usage) and the env file card (`envfile.js`) | Not built in this thread: they are not part of creation (a dialog of their own, and a pane-bar card about an existing sandbox). The create form's only template choice, "Rebuild the starting template", is ported |
| "Recent folders" | The web UI has none; favourites (starred folders) are ported |

## Not verified

  from `crates/daemon/src/http/ui.rs` (`create`, `chat`, `carve_preview`,
  `fs_browse`, `fs_pick`, `favourites_*`, `kit_mounts`, `template_status`,
  `remote_host_clone`) and `bus.rs` (`provision`), not exercised.
- **A real bring-up**: real step labels and timing, a real image pull's
  details, a remote host and its git clone, a real 409 from a real
  `sbxw.toml`.
- **The native folder picker** (`POST /api/fs/pick` runs `osascript` on
  macOS and blocks until the person picks): the app waits up to 10 minutes
  for it, off the UI thread; not tried.
- **macOS**: not built here; a real window, real typing in the inputs,
  scrolling the long form with a trackpad.

## macOS test procedure

Start the daemon (`sbxw up`), then the app with no arguments.

1. Press **New** in the top bar. The chooser shows two cards. Press
   **Workspace sandbox**.
2. The folder list shows your home. Press **Browse...**: the macOS folder
   dialog opens; pick a project folder. The list shows it, tagged
   **Selected**.
3. Type `My_App` as the name: it becomes `myapp` and the rule shows in red.
   Type the name of a sandbox that exists: "already exists" shows, Create is
   disabled. Type a free name.
4. Press ☆ on a folder row: a ★ chip appears above the list; press ☆ again:
   it goes. Close and reopen the dialog: the chip state is the same as the
   web UI's.
5. Press **Create** with no extra folder: no question; the dialog closes,
   the **New sandboxes** panel shows the steps advancing, then the panel
   closes and the sandbox's agent opens in a spare pane. Check the web UI
   lists it too.
6. New sandbox again; browse to a parent folder, press **+** on two
   sub-folders, set the second **RW**, add a port `3000` with hostname
   `app.local`. Press Create: the app's own dialog lists the extra folder
   (read-write) and the port. Press **Cancel**: nothing is created; the
   panel shows the sandbox "Waiting for you" with Retry and Dismiss. Press
   Dismiss.
7. Repeat and press **Create** in the dialog: it is created with both
   folders (check in the web UI's Ports dialog that 3000 is published).
8. In a project whose `sbxw.toml` asks for host access not approved yet
   (for example a `[[mounts]]` outside the workspace): Create shows "Allow
   host access?" with the file and the exact lines. Cancel: the card says
   "Waiting for you". Retry, then Allow: it is created. `sbxw config grants
   --revoke` forgets the approval.
9. **Restrict a sub-folder**: browse inside, press **Use this folder**; the
   preview line appears; switch Strict/Soft and see the hidden-file warning
   follow.
10. A failure: create a sandbox while Docker is stopped (or with no disk
    space): the card shows "Not created" and sbx's words; Retry once Docker
    runs: it is created.
11. **Chat sandbox**: leave the name empty and press **Start chat**: it is
    created under the suggested `chat-xxxxxx` name and its agent opens.
12. With a remote host registered (Setup, Hosts): the Host field shows; pick
    it, type a git URL, Create: the clone and then the bring-up show on the
    card.
